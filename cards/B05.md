## 题面

> 你讲完深度研究 Agent：6 个子问题并行，每个交给一个上下文隔离的子 Agent。面试官说：「团队里有人坚持单 Agent 就够了。你说并行版更好——拿什么证明？实验怎么设计才算公平？」

题面为本书自拟的训练题，不代表任何公司的真实面试题或真实系统。

| 约束 | 取值（练习设定） |
| --- | --- |
| 两个方案 | 方案 S：单 Agent 循环，自己拆子问题、检索、写报告；方案 M：代码定 6 个子问题的大纲，6 个子 Agent 并行检索，最后一个综合步骤合并 |
| 任务来源 | 过去半年分析师实际提过的研究问题，约 600 个；其中一部分有分析师写过的参考报告 |
| 判定 | 「成功」= 报告通过核查：关键事实有可核查引用、没有漏掉分析师列出的必答要点；部分要点可自动核对，其余靠评委 |
| 资源 | 同一个模型、同一套检索与抓取工具；公开网页会随时间变化 |
| 预算 | 实验总花费需要事先申请，希望控制在一个月的研究预算之内 |
| 决策方 | 研究负责人要一个明确结论：上并行版、留单 Agent，还是按任务类型分开用 |

**中途变化**：答到一半，面试官补一句——「结果出来了：并行版成功率高 8 个百分点，墙钟时间少一半，但总 token 是单 Agent 的 2.5 倍。负责人问你：该不该上？」

## 一句话框架

只在子任务真能独立、结果能合并时才试 multi-agent；证明它更好要用同一批任务、同样的模型和工具、同口径的预算做配对对照，以任务为单位算统计，把质量、时延、成本分开报。

## 追问（先口答，答不上的记进练习记录）

1. [为何不用备选] 为什么不直接拿公开基准的分数，或者直接上线做 A/B？
2. [需求变化] 负责人说：「预算只给单 Agent 的量，你的并行版还赢吗？」
3. [失败反证] 实验里并行版赢了，上线后反而更差。可能是哪里出了问题？
4. [评分偏差] 你用 LLM 评委打分，怎么保证它不偏向并行版？
5. [统计] 你跑了 50 个任务：并行版赢 12 个、输 5 个，其余两边结果相同。能下结论吗？
6. [运行] 每个方案在每个任务上跑 3 次：单 Agent 每题过 2 次，并行版每题过 3 次。这一题算谁「赢」？McNemar 还能用吗？
