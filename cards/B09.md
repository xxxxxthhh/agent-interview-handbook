# B09 · 延迟与成本（口练卡）

## 题面

> 你讲完一个会调工具的 Agent，面试官接着问：「现在 p95 要 8 秒内出完整答案，下个季度预算还要砍掉 40%。你先动哪里？怎么证明质量没掉？」

题面为本书自拟的训练题，不代表任何公司的真实面试题或真实系统。场景为虚构练习设定。

| 约束 | 取值（练习设定） |
| --- | --- |
| 系统 | 企业内部运营助手：每个请求先由模型规划，再调 2–4 个内部工具（查工单、查库存、查政策），最后由模型汇总作答 |
| 量 | 每天约 20,000 个请求，按 30 天计每月约 600,000 个 |
| SLA | 从提交到完整答案 p95 ≤ 8 秒；首字 p95 ≤ 2 秒 |
| 质量门槛 | 在现有分层评测集上，正确率与规则违反率都不能比现状差 |
| 安全 | 权限校验、输出校验不参与降级 |
| 成本 | 下季度模型费用预算比本季度少 40% |
| 数据 | 已有每个请求的整轮 trace：各段耗时、每次调用的输入输出 token |

**中途变化**：答到一半，面试官补一句——「市场部要在月底做一次推广，那三天请求量是平时的 4 倍，预算不追加。」

## 一句话框架

先用整轮 trace 找出关键路径和钱花在哪一步，再在质量与安全门槛不动的前提下，比较「少走一步」和「每步更快」各能省多少；流式只改善体感，不缩短完成时间。

## 追问（先口答，答不上的记进练习记录）

1. [为何不用备选] 为什么不直接全换成更便宜、更快的小模型？
2. [需求变化] 预算砍 40%，SLA 不变，你按什么顺序动手？
3. [失败反证] 上线并行工具调用后，p50 降了，p95 反而升了。为什么？
4. [流式] 首字已经很快了，用户还是说慢。
5. [缓存] 缓存命中率只有 20%，为什么？怎么查？
6. [成本上限] 某个请求烧掉了平均值 50 倍的 token。
7. [评估] 路由器本身怎么评估？
