## 题面

> 你刚讲完一个 Agent 的设计，面试官接着问：「你说要评估它。跑一次成功算不算过？轨迹很漂亮，却违反了一条业务规则呢？下周要换模型，你凭什么说新版能上线？」

题面为本书自拟的训练题，不代表任何公司的真实面试题或真实系统。场景沿用 A04 的合同审查系统（虚构练习设定）。

| 约束 | 取值（练习设定） |
| --- | --- |
| 被评对象 | A04 的逐条目判定流水线：每个清单条目输出一个结论（满足 / 不满足 / 缺失 / 不适用 / 无法判断）加引用 |
| 已有标注 | 60 份历史合同 × 40 条目 = 2,400 条条目判定，按清单 v1 由合规专家盲审，高风险条目双人裁决；随机抽取的「满足」项还没有双人裁决，这是现有标注的弱点 |
| 正类 | 「不满足 / 缺失」约占 10%，即约 240 条；漏报最贵 |
| 用途 | 每次改 prompt、换模型、清单改版，都要决定能不能上线 |
| 运行 | 模型输出有随机性：同一合同跑两次，个别条目结论会变 |
| 预算 | 一次发布评测要在一晚（按 8 小时计）内跑完 |

**中途变化**：答到一半，面试官补一句——「上线三个月后，线上的人工推翻率涨了一倍，可你的离线评测分数一点没变。」

## 一句话框架

评估不是一个分数：用可重置的任务集，把结果、规则遵守、轨迹和一致性分开量；结果由外部检查器或专家标签判，指标带置信区间，离线做门禁，线上盯漂移。

## 追问（先口答，答不上的记进练习记录）

1. [为何不用备选] 为什么不直接报整体准确率？为什么不干脆让 LLM 当评委，全自动？
2. [需求变化] 业务方改口了：「漏报要低，但现在误报太多，审核人被淹没了，也不行。」
3. [失败反证] 上线三个月，线上人工推翻率涨了一倍，离线分数一点没变。怎么回事？
4. [一致性] 同一份合同跑两次，有个条目一次判「满足」、一次判「不满足」。temperature 设成 0 不就好了？
5. [评委校准] 你用 LLM 当评委判「理由是否支持结论」，怎么知道评委靠谱？
6. [统计] 新版的 recall 从 90% 涨到 92%，能上线吗？
7. [版本] 清单 v2 把审计权条目的适用条件，从「所有合同」改成「仅限外包合同」。v1 的 2,400 个标签还能直接评 v2 吗？
