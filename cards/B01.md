# B01 · 编排光谱（口练卡）

> Workflow, agent, or multi-agent? · 由 content/B01.md 生成，勿手改。

## 题面

> 你刚讲完一套合同审查方案：固定流水线，模型只做逐条目判定。面试官追问：「现在大家都在做 multi-agent，你为什么不用？什么情况下你会用？」

题面为本书自拟的训练题，不代表任何公司的真实面试题或真实系统。

| 约束 | 取值（练习设定） |
| --- | --- |
| 场景 A：合同审查 | 40 个固定清单条目，每份合同逐条判定，结论要可追溯、签字人放行 |
| 场景 B：供应商尽调（面试官顺手加的） | 给一个供应商名字，查工商信息、制裁名单、负面新闻、财报、分包关系；查到分包商时还要继续查分包商 |
| 反馈 | 场景 A 有专家标注的评测集；场景 B 只有部分可自动核对的事实（名单命中、注册信息） |
| 预算与时延 | 场景 A 每份 2 个工作日内出意见；场景 B 希望 10 分钟内出初稿 |
| 错误代价 | 两个场景都是漏报比误报贵 |

**中途变化**：尽调上线了一个 multi-agent 版本后，合规官抱怨：同一份报告里，「制裁」和「负面新闻」两个子 Agent 对同一家分包商的结论互相矛盾。

## 一句话框架

代码能定的路径就用代码定；路径事先定不下、又有外部反馈时，才把控制权交给模型；只有子任务真能独立、合并成本可控时，才拆成多个 Agent。

## 追问（先口答，答不上的记进练习记录）

1. [为何不用备选] 合同审查里 40 个条目并行判定，这不就是 multi-agent 吗？
2. [需求变化] 业务方又要做供应商尽调：查到分包商就要继续查分包商。你的架构怎么变？
3. [失败反证] 尽调的 multi-agent 版本里，两个子 Agent 对同一家分包商结论矛盾，编排者选了错的那个。怎么防？
4. [公平对照] 你说 multi-agent 版本更好，怎么证明？
5. [评估] Evaluator-optimizer 什么时候反而有害？
6. [运行] Routing 把一份外包合同分进了「采购合同」的路径，用错了清单。怎么发现、怎么兜底？
